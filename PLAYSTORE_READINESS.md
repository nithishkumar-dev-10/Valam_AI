| `frontend/capacitor.config.ts` | appId `in.valam.app`, appName "Valam AI", webDir `dist`, **`server.hostname=app.valam.in`** + `androidScheme=https` |

**Key correctness decision:** Capacitor's default WebView origin is
`https://localhost`, which is **cross-site** to `api.valam.in` — the SameSite=Lax
refresh cookie would be **dropped**, so login would not persist. Setting
`server.hostname=app.valam.in` makes the WebView origin `https://app.valam.in`,
same registrable site as `api.valam.in`, so the cookie is sent. `app.valam.in` is
already in `CORS_ORIGINS`.

## 4. STILL NEEDS NITHISH (account-holder / human actions)

### Must do to launch
1. **Domain + DNS** — point `api.valam.in` and `app.valam.in` at the VM IP.
2. **Play Console account** — pay the one-time $25 and create the app
   (`in.valam.app`).
3. **Host the privacy policy** at a stable public URL and paste it into Play
   Console (see `playstore/PRIVACY_POLICY_HOSTING.md`).
4. **Signing** — on the release machine run `./scripts/gen_android_keystore.sh`,
   complete **Play App Signing**, and **back the keystore + password up offline**.
5. **Final design assets** — replace placeholders with a real 512×512 icon (no
   alpha), a 1024×500 feature graphic, and 4–8 real screenshots (or you may never
   ship — the placeholders are dev-only).
6. **Build + upload the AAB** — Android Studio → signed `app-release.aab` →
   Play Console → Production.
7. **Complete App content** in Play Console — use `DATA_SAFETY_FORM.md` verbatim;
   content rating, target audience, ads declaration.
8. **Secrets** — generate production `SECRET_KEY` and `ADMIN_ACCESS_KEY`, add the
   real `WEATHER_API_KEY`, set the production `.env` (see `DEPLOY_RUNBOOK.md` §3).
9. **Submit for review** and respond to Google's feedback.

## 5. Decisions taken (and why)

- **Capacitor over a Flutter rewrite** — reuse the existing React app; matches the
  backend and the deployed web build.
- **WebView origin = `app.valam.in`** — required for the SameSite=Lax refresh
  cookie to work inside the app (see §2).
- **No certificate pinning** in the network security config — pinning makes cert
  rotation painful for a small team; HTTPS-only + HSTS is the pragmatic choice.
- **No CAMERA permission** — the file/photo picker covers capture without granting
  the app direct camera access (also keeps the Data Safety form simpler).
- **Bake Whisper tiny+base into the image** — avoids a first-boot download and
  keeps startup deterministic; costs ~150 MB image size.
- **Postgres in compose** — enables >1 uvicorn worker; SQLite stays the default on
  the systemd path (single writer).
- **Everything left uncommitted** so you can review the full diff before it lands.

## 6. Risk register

| Risk | Severity | Mitigation |
|---|---|---|
| Docker path untested | Medium | Smoke-test `docker compose up --build` on the VM first |
| Placeholder assets accidentally shipped | High | Tracked as an explicit Nithish action (§4.5) |
| `app.valam.in` DNS/host missing → cookie dropped → login broken in app | High | Ship only after `app.valam.in` resolves and is in `CORS_ORIGINS` |
| No DB migrations | Medium | Add Alembic before any schema change |
| gTTS depends on Google's undocumented endpoint | Low | Text-only; documented in the privacy policy; replace with a keyed TTS later if needed |
| Keystore loss | High | Offline backup of `.jks` + password (§4.4) |
